# Make → Figma (standalone)
Copy a Figma Make link, paste it in the plugin, get Figma frames built from SAP kit parts: the main screen, and one frame for every popup, tab and screen the app shows. No Claude, no model at run time.
The old SAP Bridge (port 41778, `plugin/sap-bridge`) is a separate thing and is not touched.

## Set up once
1. `node make-figma/build.js`
2. `node make-figma/ctl.js start`
3. Chrome → `chrome://extensions` → Developer mode → Load unpacked → `make-figma/extension`
4. Figma → Plugins → Development → Import plugin from manifest → `make-figma/plugin/manifest.json`

## Use
1. Copy the Make **share link** (`figma.com/make/…`). A published `*.figma.site` link works too, but it skips the popup / screen scan.
2. Open the plugin, Cmd+V the link, keep Chrome in front (about 85 s).
3. Read the warning list in the plugin: every gap (a text, icon or control that did not reach Figma) is listed there.

After ANY change: `node make-figma/build.js`, close and reopen the plugin. After an extension change: reload it in `chrome://extensions` (the plugin status line shows the extension version, and "OLD" when it is too old). Current extension: **2.10.0**.
Bridge: `node make-figma/ctl.js start|stop|restart|status` (port 41779, log `make-figma/bridge.log`). Last read of an app: `make-figma/out/last-dump.json`.
Tests: `node --test test/make2tree.test.js test/make-link.test.js` (34 pass). Geometry check of the main frame: `node build/make-verify.js <dump>`.

## Parts
- **Plugin "Make → Figma"** (`plugin/`): paste the link, builds the frames. Generated by `build.js` from `plugin/sap-bridge/code.js`.
- **Bridge** (`bridge/server.js`): passes the job from the plugin to the extension, saves the result.
- **Chrome extension** (`extension/`, built by `build/make-extension.js`): opens the app in the user's own logged-in Chrome, reads it, and uses it with safe clicks only (never Save / Delete / Send …).
- **Explorer** (`build/templates/make-explore.browser.js`): one table row per new status value, dropdowns, pickers, every tab inside a popup, side pages.
- **Readers**: `build/templates/make-probe.browser.js` (SAPUI5 apps), `build/templates/make-probe-dom.browser.js` (React / web components).
- **Converter** (`build/make-convert.js`): UI5 controls (or a DOM page, via `domToUi5`) → SAP kit parts. Data tables: `build/make-map.json` (`controls`, `class_alias`, `containers_ok`), icons `knowledge/live/icons-extra.json` (156).
- **Self-check**: the converter returns `audit` and warnings (lost texts, unknown controls, missing icons, nearest colour tokens).

## State
- SAPUI5 apps: work, confirmed by the user (Maintenance, Customer Support, Purchase Orders, Flights, Build-Screen).
- React / UI5 Web Components apps (e.g. SAP Ariba Approval Flow): built (buttons, inputs, tables, roles, dialogs, SVG vectors, absolute positions, gradients, circles, pills) and tested on pages shaped like the real source — NOT yet proven on the real app.
- Known gaps: React apps are read in their open state only (no explorer); calendar popup shows the kit sample month; dropdown popovers show no ticks; frame height stops at the browser window; popups are checked by eye (the geometry check covers the main frame).

## Rules the user gave (apply to every app)
- Show every icon: a missing kit icon is read from the SAP Web UI Kit (`build/templates/icon-keys.use_figma.js`), else the closest kit icon is placed and a warning says so. Status icons are swapped into the kit status (swappable).
- Copy card styles: background, radius, kit shadow, border, padding, gaps, sizes. No exact colour token → the nearest token + a warning, never a raw colour.
- Do not repeat popups with the same status; one frame per different status / priority value, plus its tabs.
- Detect everything and build it. Never drop a component.

## Lessons (Figma plugin and kit)
- Nested nodes of a kit instance stay valid only inside ONE synchronous step; a nested swap changes sibling ids. Do texts first, icons one by one with a pause, variant swaps last. Wrap every `findOne` / `findAll` callback (ghost nodes throw).
- Not published in the kit (import fails): `Card Main Header`, `Card Numeric Header`. The Byline List Item and a status without state have no icon slot: a real icon instance is placed next to them.
- A hidden Chrome tab or an unfocused window does not open popups: the extension brings the tab and window to the front. The scan read must never silently fall back to a plain read.
- The auto-mode classifier blocks opening web pages in a browser (including headless), cookie copy and combined memory+commit+push commands. Do not work around it. `get_design_context` on a Make file key returns the REAL source files: read them to learn what a new app contains.
- A general rule can hurt another app (a global centring rule lowered the match of the saved search app): fix synthesized rows explicitly and re-run `make-verify` on all fixtures.
